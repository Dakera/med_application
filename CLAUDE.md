# med_application

Offline Flutter приложение для проверки взаимодействий лекарств (DDI-checker), русскоязычный рынок. Пользователь вводит два препарата; приложение одновременно (1) ищет пару в SQLite-таблице известных взаимодействий и (2) "минит" русскоязычные инструкции препаратов на предмет упоминаний взаимодействия, после чего объединяет оба сигнала в один результат.

## Архитектура (lib/)

- `main.dart` — точка входа, настраивает sqflite FFI для desktop, запускает `InteractionCheckScreen` напрямую. Внутри всё ещё лежит неиспользуемый Flutter counter-demo boilerplate (`MyHomePage`).
- `data/services/asset_database_opener.dart` — общий helper `openAssetDatabase()`: копирует asset-БД в documents dir (если её там ещё нет) и открывает через sqflite. Используется обоими *DbService, чтобы не дублировать эту логику.
- `data/services/db_service.dart` — синглтон `DatabaseService`, открывает `Interaction_pairs.db` через `openAssetDatabase()` с `forceRecopy: true` (dev-режим — пересоздаёт БД при каждом запуске).
- `data/services/chembl_db_service.dart` — синглтон `ChemblDbService`, открывает `chembl_37.db` через `openAssetDatabase()` с `forceRecopy: false` (read-only справочник, копируется один раз). **Вторичный/резервный источник** ATC-кода (см. `eskl_db_service.dart` ниже) — используется в UI только как fallback, если ЕСКЛП не нашёл совпадение.
- `data/services/eskl_db_service.dart` — синглтон `EsklDbService`, открывает `eskl_unique.db` через `openAssetDatabase()` с `forceRecopy: false`. **Первичный источник** для идентификации препарата (автокомплит, ATC-код, русская фармгруппа).
- `data/services/text_mining_service.dart` — чистый Dart NLP-слой: загрузка текстов инструкций, транслитерация EN↔RU названий препаратов, русский Porter-стеммер, извлечение раздела "взаимодействие" и evidence-предложений, фильтрация отрицаний ("не выявлено" и т.п.). `substanceCanonical`/`transliterate()`/`getRuName()` — путь для **ручного** текстового ввода препарата (когда пользователь печатает имя и жмёт Enter, минуя автокомплит): словарь покрывает только escitalopram/sertraline, остальное транслитерируется эвристически. Для препаратов, выбранных через автокомплит по ESKL, канонизация и RU-отображение идут другим, надёжным путём — см. `AtcRepository.resolveCanonicalName()` и `interaction_screen.dart` ниже.
- `data/repositories/interaction_repository.dart` — тонкий слой запросов к таблице `PAIRS` (`Drug_A`, `Drug_B`, `Level`) в `Interaction_pairs.db`.
- `data/repositories/atc_repository.dart` — `AtcRepository.findAtcCodes(prefName)` — JOIN `molecule_dictionary` → `molecule_atc_classification` → `atc_classification` в `chembl_37.db` по EN pref_name, возвращает `List<AtcCode>` (fallback-источник ATC/описаний, если ESKL не нашёл совпадение). Плюс **мост идентификации**: `findPrefNameByAtcCode(atcCode)`/`resolveCanonicalName(atcCodes)` — обратный запрос ATC-код → `molecule_dictionary.pref_name`, переводит препарат из мира ESKL (RU, торговое название/МНН) в "каноническое" EN-имя, по которому ищут `PAIRS`/файлы инструкций. Используется из `interaction_screen.dart` при выборе подсказки автокомплита. Если под одним ATC-кодом в ChEMBL несколько разных `pref_name` — берётся первый (детерминированно, но без специального tie-break).
- `data/repositories/eskl_repository.dart` — `EsklRepository` (`findByTradeName`/`findByInn`/`searchAutocomplete`) — точный и LIKE-поиск по `eskl_unique.db`, возвращает `List<EsklDrugEntry>`. MVP-скоуп: выдача отфильтрована только пероральными таблетками/капсулами (`_isOralTabletOrCapsule`, список `_excludeFormKeywords` вырезает вагинальные/ректальные/гомеопатические/полуфабрикатные формы, ошибочно проходящие по подстроке "ТАБЛЕТ"/"КАПСУЛ"); при неоднозначности (несколько `code_atc` под одним `(name_trade, standard_form)`) выбирается запись без составного кода (без `;`) с наибольшим `source_rows_count` (`_pickBest`/`_dedupeBy`). Детали и обоснование — в `MILESTONE_2_ESKL_INTEGRATION.md`.
- `models/` — `Interaction`, `InteractionResult` (агрегированный результат для UI: `atcCodesA`/`atcCodesB` — ChEMBL-fallback, `esklAtcCodesA`/`esklAtcCodesB` + `ftgNameRuA`/`ftgNameRuB` — первичные, из ESKL), `Evidence` (предложение+контекст), `TextSearchResult`/`InteractionStatus` (enum: confirmedByText | ddiOnly | textOnly | noData), `AtcCode` (level5/level3/level4 коды ChEMBL + их англ. описания), `EsklDrugEntry` (одна запись `eskl_unique.db`: торговое название, МНН, форма, ATC-коды/названия, `ftgNameRu`, `sourceRowsCount`).
- `presentation/screens/interaction_screen.dart` — единственный экран приложения: ввод препаратов через `TextField` с собственным debounced-автокомплитом по `EsklRepository.searchAutocomplete()` (не `Autocomplete`-виджет — его `optionsBuilder` синхронный и не подходит для асинхронных SQLite-запросов). При выборе подсказки препарат сводится к каноническому EN-имени через `AtcRepository.resolveCanonicalName(entry.atcCodes)` (мост ESKL→ChEMBL, см. выше и `MILESTONE_2_ESKL_INTEGRATION.md`) — именно оно, а не торговое название/МНН, кладётся в `selectedDrugs` и используется для `PAIRS`/инструкций. Параллельно `_ruDisplayNames` запоминает настоящее МНН из ESKL (`entry.standardInn`) для показа в чипах/карточке — в обход хрупкой `TextMiningService.getRuName()`/`transliterate()`, которая остаётся fallback'ом только для ручного ввода. Карточка результата показывает строку ATC-кода + русской фармгруппы по каждому препарату, с fallback на ChEMBL.
- `presentation/widgets/interaction_card.dart` — похоже, мёртвый код (экран рендерит результат сам, инлайново).

## Данные (assets/)

- `database/Interaction_pairs.db` — таблица `PAIRS`: Drug_A, Drug_B, Level. Используется через `DatabaseService`/`InteractionRepository`. **Важно (было задокументировано неверно до Milestone 2)**: это не таблица на 7-8 препаратов, а полноценная база вроде DrugBank — Drug_A/Drug_B содержат ~1940 уникальных действующих веществ на английском (в нижнем регистре: `abacavir` ... `zopiclone`). Проверка идёт по строке точного совпадения — реальное ограничение было не в PAIRS, а в том, как препарат сводился к этой EN-строке (см. `AtcRepository.resolveCanonicalName()` выше и `TextMiningService`).
- `database/eskl_unique.db` — **первичный источник** данных о препарате, собран из официальной базы ЕСКЛП (nsi.rosminzdrav.ru). Таблица `eskl_unique` (21563 строки, индексы на `code_atc`/`name_trade`/`standard_inn`): `name_trade`/`standard_inn` (торговое название/МНН, ВЕРХНИЙ РЕГИСТР), `standard_form` (лекарственная форма), `code_atc`/`name_atc` (могут быть составными через `;` — комбинированный препарат), `ftg_name_ru` (русское название фармгруппы — то, ради чего затевалось), `source_rows_count` (индикатор распространённости для сортировки/tie-break). **Важно**: SQLite `UPPER()`/`LOWER()` не работают с кириллицей — регистронезависимость реализована через `.toUpperCase()` в Dart до построения SQL-запроса, не в SQL. Используется через `EsklDbService`/`EsklRepository`. Подробности схемы и решения по неоднозначности данных — `MILESTONE_2_ESKL_INTEGRATION.md`.
- `database/chembl_37.db` — публичная база ChEMBL 37, используется через `ChemblDbService`/`AtcRepository` для получения ATC-кодов препарата по латинскому (канонич.) названию (`molecule_dictionary.pref_name`, регистронезависимо). **Вторичный/резервный источник** — в UI задействуется только как fallback, если `eskl_unique.db` не нашёл совпадение. Схема описана в `chembl_atc_trade_schema.drawio` (в корне проекта). Ключевые таблицы: `atc_classification` (level1..level5 коды + описания), `molecule_dictionary` (molregno, pref_name), `molecule_atc_classification` (связка молекула↔ATC), `molecule_synonyms`/`products`/`formulations` (торговые названия — не подключены к UI).
- `instructions/*.txt` — инструкции по 7 препаратам: carbamazepine, citalopram, digoxin, escitalopram, fluoxetine, ibuprofen, paroxetine, sertraline. Не связано с ESKL — подбирается по "каноническому" EN-имени из `TextMiningService`.
- `data/test_data.json` — legacy, оставшийся после миграции на SQLite (commit `1fc5b1b`), похоже больше не читается.

## Стек

sqflite + sqflite_common_ffi, path_provider. Без state-management пакета — обычный `StatefulWidget`/`setState`. Без сети — всё офлайн (bundled DB + bundled тексты инструкций).

## Известные проблемы / незавершённое

- `DatabaseService` пересоздаёт `Interaction_pairs.db` из asset при **каждом** запуске (`forceRecopy: true`, dev-режим) — нужно поправить перед релизом. `ChemblDbService` так не делает (`forceRecopy: false`).
- Торговые названия из `chembl_37.db` (`molecule_synonyms`/`products`) пока не подключены к UI — только ATC-коды (level5). Русские названия фармгрупп теперь берутся из `eskl_unique.db` (`ftg_name_ru`), а не из ChEMBL.
- Словарь канонизации названий (`substanceCanonical`/`substanceNames`) покрывает только escitalopram и sertraline (по 2 ключа каждый — RU и EN написание); остальное идёт через хрупкую эвристическую транслитерацию (`TextMiningService.transliterate()`). Актуально только для **ручного** ввода текста в поле (Enter/кнопка "+" без выбора подсказки) — препараты, выбранные через автокомплит, канонизируются надёжно через `AtcRepository.resolveCanonicalName()` (ATC-мост), в обход этого словаря.
- **ATC-мост (ESKL→ChEMBL) резолвит DDI-проверку не для всех 21к+ препаратов ESKL.** `resolveCanonicalName()` работает, только если: (а) у препарата в ESKL есть непустой `code_atc`, и (б) этот ATC-код есть и в `chembl_37.db`. Для некоторых записей ESKL (особенно нишевых/локальных позиций, отсутствующих в глобальной ChEMBL-номенклатуре) моста не будет — тогда `selectedDrugs` получает МНН как есть, `PAIRS`/инструкция для него просто не найдутся (штатная ветка "не найдено", не баг), а ATC/фармгруппа на карточке результата всё равно отобразятся напрямую из ESKL. Также: если под одним ATC-кодом в ChEMBL несколько разных `pref_name` (комбинированные коды) — берётся первый попавшийся, без специального tie-break; составные `code_atc` (`"A;B"`) перебираются по компонентам по очереди.
- Файлы инструкций (`assets/instructions/*.txt`) — жёсткое, контентное ограничение: их всего 8 (carbamazepine, citalopram, digoxin, escitalopram, fluoxetine, ibuprofen, paroxetine, sertraline), и ATC-мост это не расширяет — просто нет текста инструкции для остальных препаратов. DDI-проверка по `PAIRS` (см. выше) теперь потенциально работает для любого препарата из ESKL, но её текстовое подтверждение (`confirmedByText`) в результате — только если один из двух выбранных препаратов входит в эти 8.
- Список выбранных препаратов не жёстко ограничен двумя (проверка только `>= 2`), при этом код использует `selectedDrugs[0]`/`[1]` — 3-й препарат молча игнорируется.
- Мёртвый/legacy код: `InteractionCard` widget, закомментированные старые методы, debug `print(count)` в `interaction_repository.dart`, неиспользуемый `test_data.json`.
- **Подсвеченная evidence-фраза теряет родительский контекст.** `extractSection` схлопывает все переносы строк в пробелы, из-за чего `extractEvidence` (`text_mining_service.dart`) никогда не видит структуру буллет-списков — вся секция уходит в одну "line", которая режется по `[.!?;]` на клаузы. После фикса разбиения по `;` (было: гигантский блок из десятка категорий склеенных через `;`) каждая клауза стала короткой и точной, но конкретный препарат в списке (например "• антидепрессанты: ..., сертралин, ...;") теперь подсвечивается без заголовка типа "Влияние карбамазепина на концентрацию в плазме препаратов... следующих ЛС:", который лежит на несколько предложений/абзацев выше — пользователю не всегда понятно, к чему относится подсвеченный фрагмент. Простого решения нет: чтобы вернуть заголовок, `extractSection`/`extractEvidence` нужно переработать так, чтобы сохранять структуру строк (не схлопывать `\n`) и корректно матчить заголовок к каждому буллету — не точечная правка.

## История

Развитие: JSON-прототип → SQLite data layer → clean architecture (data/models/presentation) → единая модель `InteractionResult` → интеграция `eskl_unique.db` как первичного источника идентификации препарата (Milestone 2, план — `MILESTONE_2_ESKL_INTEGRATION.md`), ChEMBL переведён в статус fallback. Первая версия UI-автокомплита добавляла в чипы торговое название напрямую — это ломало DDI-проверку и поиск по инструкции (обе завязаны на "каноническое" EN-имя действующего вещества). При разборе проблемы выяснилось, что `PAIRS` на деле покрывает ~1940 веществ (а не 7-8, как считалось изначально) — так что решением стал не откат, а ATC-мост `AtcRepository.resolveCanonicalName()` (ESKL `code_atc` → ChEMBL `pref_name`), который сводит любой выбранный через автокомплит препарат к правильному каноническому имени независимо от того, было введено торговое название или МНН. Текстовый майнинг по инструкциям остаётся ограничен 8 файлами — это контентное, не программное ограничение. На момент написания — незакоммиченный рефакторинг Milestone 2.
